# D02 — Product direction: reproduce the ReciMe use case, with browser access and automatic categories
- Date, owner: 2026-10-22, Paweł Wójcik (founder)
- Context and the options weighed: Competitive research shows ReciMe, Stasht and Sorti already cover social/web/YouTube recipe import. The founder named ReciMe as the exact use case and named two gaps in it (their statement; whether they have used ReciMe was not stated): no browser support, no automatic categorisation into categories they define (examples given: sport exercises, cooking, fun).
- Decision and why: Build the ReciMe-style import (link in, readable recipe out) plus browser access and automatic assignment to a fixed set of categories chosen by the founder. Origin: the founder's own statement, not an agent recommendation.
- Consequences, and what would make us revisit it: The differentiators rest on the founder's reading of ReciMe, which conflicts with the vendor's own platform listing (web app, Chrome extension). Revisit after the ReciMe check in Q01.
- Status: active

## Update 2026-10-22 (founder)
- The founder corrected the premise: "I missunderstood recime - it has browser extension." Browser support is not a gap in ReciMe. The direction stands for the founder's own reasons; see D10.
